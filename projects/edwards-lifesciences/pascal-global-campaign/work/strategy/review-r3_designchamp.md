Question, as rounds 1–2: does the CCI hand us an image, demonstration or visual proof that can carry one global system across congress, detail aid and digital?

## Ratings

| CCI | Rating | Reason |
|---|---|---|
| **D-A** "what a heart team has proved with PASCAL becomes how it works" | **SHOWABLE** | "Proved" is an artifact the team already holds (their own read, their own log, their own case record) and "how it works" is that same artifact sitting in an ordinary context (the scheduled list, the other valve, a new site). That is a constant/variable pair with real things on both sides, not an abstraction. |
| **D-B** "a heart team's PASCAL experience never has to start over" | **THIN** | The image it hands us is a negative (a restart that does not happen). Showing absence needs a before/after or a counterfactual, which pulls in the reset/loop/blank-page cliché and, on the valve chapter, a split-screen comparison with Abbott's two names. Workable on E3 only; it does not carry E1, E2 or E4. |

## Does D-A still support repetition with change on a real constant?

**Yes, and better than V1.** V1's constant was implied by "further"; D-A names it. The constant is the team's proof, shown as a real object (imaging read, case log, the PASCAL device's form, the same team), and the change is the context where it now operates. "Becomes" is a state change, not a direction, so it needs no arrow, path or journey to be shown; the round-2 ban list holds without strain.

| Surface | How the constant carries | Watch |
|---|---|---|
| Congress | Large-format: the team's own proof artifact at scale, with the new context named beside it. Booth episodes rotate the context, never the constant | Must not default to E1's echo look as the system (rule 5) |
| Detail aid | Sequential pages suit "proved → how it works" as two plain states of the same artifact; this is where E2's owned fact (log, list) lives best | Two-state pages must not open on the hard case (hard-case rule) |
| Digital | At 300x250 only the context line changes against a fixed constant crop; holds as a series | Small sizes cannot carry a dense read; constant needs a simple recognizable crop (device form or team) |

## Risks and conditions

1. **"Proved" invites the trophy/evidence cliché**: certificates, stamps, checkmarks, data bars, trial charts. Ban them. Proof is the team's working artifact, never a badge, and never paired with outcome data in the same frame (matches MLR note §4).
2. **"Proved" can pull the hard case into frame one.** The proof artifact is shown in the ordinary context, not recalled from the demanding case. Hard case stays off-image as provenance.
3. **E2 is still the thinnest episode.** D-A helps (the team's own log is a "proved" object), but it still needs an owned fact per story before DEVELOP.
4. **E4 and E5 unchanged**: E4 has nothing to show until O5; E5 risks the floating-device cliché.
5. Dependencies unchanged: real imaging, real teams, real case access (consent and claims ⚑, O3, O5). No generated physicians, patients, procedures or Edwards product, even in comps.

## Note for the gate

D-A passes the show test and is the stronger visual system of the two. D-B should stay a verbal fallback only; if chosen, it needs E3 to carry the launch and the system would narrow to the valve story.
