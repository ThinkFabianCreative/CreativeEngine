### D1 detail: tiered case template (proposal)

One content type, one set of fields, three tiers. A tier is set by what the client allows and what results exist, never by how much we like the work. A case can move up a tier when results or permission land.

| Field | Deck origin | Tier A Episode (hero, full) | Tier B Supporting | Tier C Restricted (regulated / no results yet) |
|---|---|---|---|---|
| Client, three tags (division · service · industry) | deck | required | required | required |
| **The rule** (one named rule, regulation, approval step or category habit that became the material) | new, CCI rule 1 | required; must pass remove-the-rule test | optional, one line if it passes; otherwise left blank, never invented | optional, one line |
| Challenge (two lines) | deck | required | required | required |
| What we did (three lines) | deck | required | required (can be one) | required (one line) |
| **The brave version** (what we first proposed) | new, CCI rule 2 | required where client allows (A8) | — | — |
| **What review changed** (what the reviewer actually did; real markup allowed only here) | new, CCI rule 2 | required where client allows (A8) | — | — |
| How we did it / media | deck | full | one asset | one still (or approved frame) |
| **Results** (flexible slot: 0–3 items, each with source + year; a qualitative outcome or "results pending, date" is a valid entry; weak numbers allowed) | deck "three numbers", loosened | 1–3 | exactly 1 or "pending" | 0 allowed |
| Quote (one line) | deck | required | optional | required (often the main proof) |
| **Team on the account** (names / roles, tenure) | new, V2 / A10 | optional, tests in EXPLORE | — | optional |
| Related work (three tiles by tag), next step | deck | required | required | required |

Why this works for both: the monthly cadence fills a Tier B or C case from the CMS in an afternoon; Tier A is the only tier that needs the candor interview, and only six exist at launch. Not every case is a CCI episode, which matches the packet's "do not assume". The verification rule rides on the Results field (source + year required to publish), which turns C1–C7 checking into a field state instead of a separate list.

Open for Andres: whether "what review changed" is published as text, as the actual markup, or both; that depends on A8 per client.
