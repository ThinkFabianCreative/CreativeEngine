# New frameworks: first live test

```
DATE:        2026-09-17
FRAMEWORKS:  shared/frameworks/selling-the-work.md · shared/frameworks/typography.md
TESTED ON:   one live client project in DEVELOP, with a client deck, a type-led retargeting system and
             earlier human-directed reviews to compare against. Applied output is filed in that
             project's work/reviews/ (selling-typography-review_v01). This record holds no client facts.
NOT TESTED:  narrative-craft.md. The project has no script or edited video yet; one deck page described
             a planned video, which is not enough to judge the framework.
QUESTION:    Does each framework produce judgment we didn't already have, or paperwork?
```

## Verdict by framework

### selling-the-work.md — useful. Produced the most important finding of the pass

| Section | Result on live work |
|---|---|
| §1 defense | **New value.** Forced the WHY THIS swap test, which the idea passed cleanly, and surfaced that the strongest cost-of-safe argument rested on an agency-authored document |
| §2 decision chain | **Most valuable section.** Found that the idea's entire ownability sat in one brand asset owned by a different part of the client organization than the team being presented to. No earlier review had framed it as an approval-chain risk |
| §3 objections | **Mixed.** Diagnosed several objections usefully. But the objection most likely to kill the work, "this isn't what we briefed", had **no row**. Defect |
| §4 load-bearing | **New value.** Produced a concrete concession list and forced a decision nobody had made: what happens if the brand asset is refused |
| §5 what to show | Partly duplicated an earlier deck review (no recommendation; unsafe testimonial route). Added "only show work you want made" as the reason, which changes the fix from "correct it" to "decide whether to show it" |
| §6 pre-compromise | **Worked in an unexpected direction.** It caught weaker lines *added* to the deck and a strong exploration lead *missing* with no recorded reason. The first draft of the review wrongly called that omission deliberate; the section's own test ("who decided?") caught the overstatement |
| §8 honesty | Caught two items: an unsupported audience claim, and a quoted line attributed to the client's existing campaign whose source was unconfirmed |

### typography.md — useful as a verifier. Modest new findings on well-crafted work

| Section | Result on live work |
|---|---|
| §1 / §10 locked system | Correctly identified that selection filters (§2) don't apply when the face is mandated, and routed judgment to §10. Caught a brand-rule breach (logo on an accent color) |
| §4 hierarchy | **Two real findings.** Three accent-colored elements on one frame (nothing emphasized), and, in a spec that was otherwise sound, the one witty word set at the smallest size with no mark distinguishing it |
| §6 micro | **Concrete catches.** Straight apostrophes in copy handed to a production agent that was told not to alter quoted words, and an acute accent used as an apostrophe on a client-facing page |
| §8 legibility | Verified contrast ratios by calculation: the spec's figures were right. Confirmation, not discovery |
| §9 tells | **Near-miss defect.** The list includes "quirky script" and trend faces, but the client's own licensed script campaign face would have tripped it. Nothing said a mandated face is exempt |

On a type system a designer had already built carefully, the framework mostly confirmed good decisions. That's still worth something (it replaced "looks right" with checked numbers), but its value will be higher on early comps than on mature specs.

## Defects found and fixed

| Framework | Defect | Fix |
|---|---|---|
| selling-the-work | No "this isn't what we briefed" objection, the likeliest killer in real presentations | Added row §3: not answerable by defending the idea; show the brief's words and the bridge; brief conflicts go to the client and `brief-machine` |
| selling-the-work | No role for a brand-asset owner outside the client team | Added §2 row "Brand owner elsewhere" and a consequence: find where the idea's ownability lives |
| selling-the-work | EVIDENCE status didn't distinguish agency-authored material | §1: evidence includes its author; our own plans are our read, not independent support |
| selling-the-work | Legal row too narrow for brand-asset approvals | §3 row generalized to "Legal / brand won't approve it" |
| typography | Tells list could fire on a client's own mandated face | §9: a client's licensed or mandated face is never a tell; judge it only by its rules (§10) |
| typography | Correct-marks rule didn't reach the production handoff | §6: accent substitutes named; fix marks in copy handed to production |

## Method notes

- **Check the asset version before reviewing it.** The deck on disk was a later export than the one the earlier review covered, and 20 of its 24 pages differed. The test would have critiqued stale work if that hadn't been checked. It applies to any review of supplied files and isn't specific to either framework.
- **Rendering matters for typography.** Font metadata in design-tool PDF exports was stripped (unnamed Type 3 fonts), so typeface questions could only be answered by rendering and looking at pages.
- **The framework output blocks worked** as a forcing format for §1. They were not produced for typography, where findings-as-table read better. That's consistent with both frameworks' "don't produce this wrapper when it makes the answer worse" rule.
