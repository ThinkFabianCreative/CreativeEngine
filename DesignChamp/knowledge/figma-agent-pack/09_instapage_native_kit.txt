09 · INSTAPAGE NATIVE KIT (LANDING PAGES BUILT IN INSTAPAGE ONLY)
Derived from .claude/skills/instapage-production/references/figma-kit.md and
platform.md (verified 2026-09-24). Those files win if anything here disagrees.
Read only when the request says the landing page will be produced in Instapage.

WHAT THIS IS
You are drawing a landing-page SPECIFICATION that a person will rebuild natively
inside Instapage. Ordinary content maps to native elements. Document required integration exceptions
with external editing/maintenance owners; do not claim embedded CRM fields are native.
The kit file: "CreativeEngine · Instapage Native Kit"
https://www.figma.com/design/suQoQdAczG3IZRVMxooqpb

THREE LAYERS: KEEP THEM APART
Layer 1  The kit's IP primitives. Neutral grey wireframes. They carry structure, not
         style. These are replaceable conventions; client-approved styling and bindings govern.
Layer 2  The client's own library (client files 10+): faces, colors, buttons, forms,
         imagery, client components named <Client> / <Section> / <Variant>.
Layer 3  This page: layout, composition, hierarchy, copy placement, mobile order.
Never use another client's library, colors, fonts, blocks or layouts.
Never create or reuse a "CreativeEngine" house style.
Never pick a template because it is close. Build what the request specifies.

HOW TO BUILD THE SPEC
- Desktop/mobile frames: 1440/400 are preview conventions, not universal dimensions.
  Same blocks, same IDs, same order in both.
- Each section is a BLOCK: a full-width frame named "B01 · <section> · Fluid Grid"
  or "B01 · <section> · Canvas". Number blocks top to bottom.
- Figma GRID expresses intended Fluid Grid structure, not proven runtime equivalence.
  Vendor-suggested 20 px side padding is guidance, not a hard platform minimum.
- Inside it, each CONTAINER is an auto-layout frame spanning grid cells, named
  "B01.C1 · m1" where m1 = its position when stacked on mobile.
  Document intended native container settings: direction, alignment, gap, padding, fill color or
  image, border, corner radius. Validate mappings in the actual builder.
- Every element is an instance of a kit primitive (IP / Headline, IP / Paragraph,
  IP / Button, IP / Image, IP / Video, IP / Line, IP / Form, IP / Timer,
  IP / Accordion, IP / Carousel) or of a client component built from them.
  Restyle instances with the client's faces and colors.
- Name elements with IDs: "E01 · Headline h1", "E05 · Image · IMG-01".

COMPOSITE FIXTURES AND SEMANTIC PLACEHOLDERS
- The eight composites on Molecules & organisms are preserved mapping fixtures,
  never client starters or universal hero/CTA layouts. The approved spec dictates composition.
- Preserve Semantic token/style bindings, but define approved client values and any
  client-specific names in the isolated client library. Spacing/radius/opacity values
  in this kit are replaceable preview placeholders, not global design standards.
- Overlay and other composite native mappings require workspace evidence; no runtime
  or editor-authorability guarantee follows from a Figma component.

LIMITS YOU MUST DESIGN WITHIN
- Only three font roles per page: headline, paragraph, button. Forms use the
  paragraph face, and form field text size cannot be changed.
- At most 14 entries in Instapage Styles; this is not the full client palette limit.
- No box or circle shapes inside a Fluid Grid block. Use container fill, border and
  radius, or make that section a Canvas block.
- Accordion sections: text only. No links or images inside.
- Timer: counts down to one fixed date only. No labels on mobile.
- Video: YouTube, Vimeo or Wistia. No uploaded or looping video.
- Popup background controls require workspace verification; no universal client color.
- Reparenting on mobile is documented to change desktop structure too; verify workspace
  behavior. Independent placements need explicit device intent and approved duplicates.
- Exactly one h1 on the page.
- Text must stay real text. Never set copy inside an image to get a look.
- Never recreate ordinary native content in custom code. A required CRM embed may
  have an approved INTEGRATION exception with named owners and tested tracking.
  Report other native gaps with alternatives; do not invent support.

ANNOTATIONS (use Figma annotations, not visible text on the design)
  IP · Copy       copy ID of the text on this layer (from the approved copy doc)
  IP · Asset      image asset ID and status (PLACEHOLDER or PRODUCTION-APPROVED)
  IP · Build      link target, visibility, sticky, form settings, conversion goal
  IP · Reuse      Page-local / My Block / Global Block (+ reason) on each block
  IP · Exception  anything that is not native, with the native options
Repeat shared annotations on both devices and lint stable IDs; no implicit inheritance.
Preserve client variable/style bindings; Instapage Styles is not a live token sync.
Reuse tags (IP / Tag) go in the margin beside the block, never inside the design.

IMAGES
Use only supplied, approved images or labelled placeholders. Never generate an image
for a production spec. Placeholder label: "PLACEHOLDER IMAGE · <asset ID> · not for
external use".

REPORT ALSO
- Any section you could not draw with native primitives, and why.
- Any copy that does not fit, with the element ID. Do not shorten it.
- Any place where mobile order differs from desktop order.
